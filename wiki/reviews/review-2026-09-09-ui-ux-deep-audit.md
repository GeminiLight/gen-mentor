# GenMentor UI / UX 深度审视

审视日期：2026-09-09。代码基线：`467878a`。性质：原始评审与修改建议。后续精修处置见 `wiki/85-backlog.md` 与路线图；下列复现描述保留审计时的原始状态。

当前已经有统一的基础组件、清晰的中性色系、双主题、阶段反馈、本地档案与完整页面。
但离优秀学习产品的主要差距在于：学习证据不够可靠、跨步骤状态不能稳定保留、核心阅读任务容易被外围流程阻塞，以及页面仍然以系统模块组织，而不是围绕学习者此刻的行动组织。

保留现有技术栈和专业克制的方向。下一轮的主线应是：**让学习者清楚知道学什么、可以立即开始、能放心中断、回来后能继续，并知道自己究竟学会了什么。**

- 专项探针：[基础探针](../../e2e/artifacts/ui-audit-20260909/probe.mjs)、[补充探针](../../e2e/artifacts/ui-audit-20260909/probe-extra.mjs)；[结果一](../../e2e/artifacts/ui-audit-20260909/findings.json)、[结果二](../../e2e/artifacts/ui-audit-20260909/findings-extra.json)。这些是本地审计产物，不是新增到正式测试集的回归用例。

## 已确认的缺陷

### F01 · P1 · 多选题选第一项后立即锁定

- **复现**：题目“请选择两个偶数”，选项 2、4、3，正确集合是 2 和 4。勾选 2 后三个复选框全部 disabled，出现“错误”，确认按钮消失。
- **原因**：`quiz-view.tsx` 每次选择都调用 `judge`；`locked` 直接依据实时 verdict，而确认按钮只更新答题顺序，不控制判定。
- **方向**：多选题区分“编辑选择”和“确认作答”；确认前允许勾选、撤销，确认后判分和锁定。
- **验收**：可以选中 2、4 再确认得到正确；单选 2 在确认前不显示错误；连击只在确认后变化。
- **位置 / 证据**：[quiz-view.tsx](../../app/src/features/session/quiz-view.tsx)、[截图](../../e2e/artifacts/ui-audit-20260909/multiple-choice-lock.png)。

### F02 · P1 · 阅读与测验切换会清空未提交答案

- **复现**：测验选择一个答案 → 切到阅读 → 返回测验，原选择从 true 变为 false。
- **原因**：答案仅放在 `QuizView` 本地状态，Tab 内容卸载后丢失；只有交卷才写入档案。
- **方向**：按稳定课程标识保存测验草稿；切页、刷新、查看教材都保留答案、确认状态与答题顺序。草稿与已交卷结果分开。
- **验收**：选择题和简答题经 Tab 切换、路由离开、刷新均可恢复；恢复草稿不得伪造一次新提交。
- **位置**：[quiz-view.tsx](../../app/src/features/session/quiz-view.tsx)、[session-reader.tsx](../../app/src/features/session/session-reader.tsx)。

### F03 · P1 · 简答题未评分，却被计入正确率分母

- **复现**：只有一道简答题“2 加 2 等于多少”，正确填写 4，交卷显示“答对 0 / 1 题”。
- **原因**：简答题 verdict 为 `answered`，但 `answered` 仍增加；总分、进度页和 `quizPerformance` 都按 correct / answered 计算。
- **方向**：明确区分“已作答”“已评分”“待评价”；自动正确率只计算可判分题，简答题单独展示自评或待导师评价状态。
- **验收**：只有简答题时不显示 0% 正确率；传给画像的学习证据也不得把未评分当错误。
- **位置 / 证据**：[quiz.ts](../../app/src/lib/quiz.ts)、[截图](../../e2e/artifacts/ui-audit-20260909/short-answer-score.png)。

### F04 · P1 · 漏答题被静默跳过，交卷后又无法继续

- **复现**：四题只答对一题就交卷，显示“答对 1 / 1 题”，另三题仍未作答，但所有输入已禁用。
- **影响**：用户容易把局部正确率理解为整次测验表现，同时没有补答入口。
- **方向**：交卷前列出漏答数量、跳转到未答题；允许明确选择提前结束。成绩同时展示“已答 / 总题数”和“正确 / 已评分”，补答或重测应保留历史。
- **验收**：一题作答不能呈现为完整测验满分；提前交卷有明确提示；可以重新练习而无需重生成教材。
- **位置**：[quiz-view.tsx](../../app/src/features/session/quiz-view.tsx)、[quiz-status.tsx](../../app/src/features/session/quiz-status.tsx)。

### F05 · P1 · 重排路径后，新课名可能对应旧教材和旧测验

- **复现**：先为索引 1 的 Pandas 课保存匹配教材，再把未完成课程 1、2 调换。打开 `/session/1`，页标题成为 Data Cleaning and Preparation，正文仍是 Working with Pandas DataFrames。
- **原因**：内容按 `goalId:index` 存储；重排只替换 `learning_path`，没有迁移或失效旧 session 内容。URL 也依赖索引和当前激活目标。
- **方向**：课程使用客户端生成的稳定标识；重排以课程身份匹配，未改变的保留，实质改变的内容失效或保留为旧版本；书签包含目标与课程身份。
- **验收**：交换顺序、插入、删除、重写未完成课后，教材、测验、完成状态和足迹都跟随课程身份；切换目标不改变同一书签的含义。
- **位置 / 证据**：[reschedule-dialog.tsx](../../app/src/features/path/reschedule-dialog.tsx)、[derive.ts](../../app/src/lib/store/derive.ts)、[截图](../../e2e/artifacts/ui-audit-20260909/reschedule-stale-document.png)。

### F06 · P1 · 出题失败会把已经保存的教材一起挡住

- **复现**：档案已有完整文档，缺少 quiz；模拟出题 503，页面只剩流水线与“生成失败”，阅读区和 Tabs 都为 0。
- **原因**：`!doc || !quiz || running` 会让整块学习界面进入流水线。
- **方向**：文档一旦可读就开放阅读；测验拥有独立的生成、重试和错误状态。预览、教材、测验分别表达就绪程度。
- **验收**：出题慢或失败时可完整阅读和向导师提问，只有测验区显示等待与重试。
- **位置 / 证据**：[session-view.tsx](../../app/src/features/session/session-view.tsx)、[截图](../../e2e/artifacts/ui-audit-20260909/quiz-failure-blocks-reader.png)。

### F07 · P1 · 导入档案会直接覆盖现有全部目标

- **复现**：已有 `g_seed`，上传只包含 `g_import` 的档案，没有确认弹窗，存储立即只剩 `g_import`。
- **方向**：先预览文件、目标数量、时间和影响范围；明确选择合并或替换。替换前提供备份，验证失败不能触碰原档案。
- **验收**：取消导入后原档案完全不变；替换需要明确动作；同名或同 ID 目标有可解释的处理方式。
- **位置**：[archive-panel.tsx](../../app/src/features/profile/archive-panel.tsx)、[store/index.ts](../../app/src/lib/store/index.ts)。

### F08 · P1 · 不完整的导入文件会写坏档案并导致崩溃

- **复现**：导入 `version:1`、一个只有 `id`、`learner_profile:{}`、`learning_path:[]` 的目标；校验通过并写入，随后报 `Cannot read properties of undefined (reading 'length')`，显示英文崩溃页。
- **方向**：档案使用完整 schema 校验、版本迁移和关系一致性校验，全部通过后原子替换。异常恢复入口必须能导出原始数据和恢复备份。
- **验收**：缺少 cognitive_status、sessions 或错误 active_goal_id 的文件在写入前被拒绝，原档案及可用界面不变。
- **位置**：[archive.ts](../../app/src/lib/store/archive.ts)、[archive-panel.tsx](../../app/src/features/profile/archive-panel.tsx)。

### F09 · P2 · 创建目标的草稿刷新即丢，阶段恢复也只在当前组件有效

- **复现**：填写目标、背景后刷新，两项都变成空字符串。
- **原因**：表单在 useState 中，已完成步骤在 `useOnboarding` 的 useRef 中；最后成功才创建 Goal。
- **方向**：独立保存 onboarding 草稿与已完成阶段，显示“草稿已保存在此设备”；提供继续、重新开始与清除草稿。
- **验收**：刷新恢复输入；模型阶段中断后可恢复已完成部分，且修改输入会正确使相关阶段失效。
- **位置**：[goal-form.tsx](../../app/src/features/onboarding/goal-form.tsx)、[use-onboarding.ts](../../app/src/features/onboarding/use-onboarding.ts)。

### F10 · P1 · 中文输入法确认候选词可能触发导师发送

- **复现**：向输入框派发 `Enter + isComposing:true`，产生一次 tutor 请求，输入框被清空。
- **原因**：onKeyDown 只判断 Enter 和 Shift，没有排除组合输入。
- **方向**：组合输入期间不发送；保留 Enter 发送、Shift+Enter 换行的可见提示，必要时按设备调整。
- **验收**：自动化 composition 测试无发送；再用 macOS 中文输入法和实体手机输入法验证。当前复现是事件级，未冒充实体输入法测试。
- **位置**：[tutor-sheet.tsx](../../app/src/features/tutor/tutor-sheet.tsx)。

### F11 · P2 · 导师聊天一键清空，没有确认或撤销

- **复现**：点击“清空”后历史从两条变为 0；仅有原导师 Sheet，未出现确认对话框。
- **方向**：清空前说明影响当前目标下的全部对话，并支持取消；或实现可靠撤销后再采用即时清空。
- **验收**：误触可以恢复，正在生成时清空不会让旧回复重新写回。
- **位置**：[tutor-sheet.tsx](../../app/src/features/tutor/tutor-sheet.tsx)。

### F12 · P2 · 带代码或加粗的章节标题，目录无法定位

- **复现**：目录“使用 `groupby()` 聚合”指向 `使用-groupby-聚合`，实际标题 ID 为 `使用-聚合`；“理解 **数据清洗**”指向 `理解-数据清洗`，实际 ID 为 `理解`。
- **原因**：目录解析原始 Markdown，标题 ID 的 `textOf` 不读取 React 元素中的文本，二者来源不一致。
- **方向**：用同一 Markdown 语法树生成目录与标题 ID，并统一重复标题去重规则；目录显示纯文本。
- **验收**：代码、强调、链接、重复标题、中文标题都能跳转正确位置。
- **位置**：[document-toc.tsx](../../app/src/features/session/document-toc.tsx)、[document-view.tsx](../../app/src/features/session/document-view.tsx)。

### F13 · P1 · 下一课长标题撑破手机页面

- **复现**：392px 视口，下一课标题为一条正常长度的中文课程说明；按钮宽 555px，页面 scrollWidth 为 571px，产生整页横向滚动。
- **原因**：Button 默认 `shrink-0 whitespace-nowrap`，下一课把整个标题放入按钮，容器没有适当的宽度约束。
- **方向**：动作保持短标签“下一课”，课名单独显示并允许换行；阅读页所有长内容只能在自身容器内滚动。
- **验收**：320、392、768px 下长中英文课名不造成页面横向滚动，动作和完整课名均可访问。
- **位置 / 证据**：[session-reader.tsx](../../app/src/features/session/session-reader.tsx)、[截图](../../e2e/artifacts/ui-audit-20260909/mobile-reader-long-title.png)。

### F14 · P1 · 短视口下模型弹窗超出屏幕

- **复现**：667 × 375 视口，Dialog 高 465px，top=-45、bottom=420；自身 overflow 为 visible，标题和底部操作超出视口。
- **方向**：弹窗有基于可用视口的最大高度，内容区滚动，标题与底部动作可达；再验证软键盘和安全区。
- **验收**：横屏、低高度窗口、文本放大时可以看到标题、关闭、测试、保存，并能键盘遍历完整表单。
- **位置 / 证据**：[dialog.tsx](../../app/src/components/ui/dialog.tsx)、[截图](../../e2e/artifacts/ui-audit-20260909/settings-short-viewport.png)。

### F15 · P1 · 模型表单展示的默认值与实际调用值不同

- **代码证据**：OpenAI 表单占位显示 gpt-4.1-mini / gpt-4.1；不填写时 `byokFromRequest` 实际使用 glm-5.3-flash / glm-5.3-flash；接口地址留空则走 SDK 默认地址。
- **影响**：用户只填密钥时，界面让其以为采用占位模型，实际使用另一个模型；是否被供应商拒绝取决于端点，本轮没有真调用验证。
- **方向**：供应商预设与实际配置同源，明确区分官方服务与兼容网关；展示实际采用的模型，不能让 placeholder 冒充默认值。
- **验收**：只填密钥时，界面呈现的最终端点和模型与请求一致；切换供应商不残留前一供应商参数。
- **位置**：[model-settings.tsx](../../app/src/features/settings/model-settings.tsx)、[config.ts](../../app/src/lib/llm/config.ts)。

### F16 · P2 · “模型就绪”只代表存在配置，未代表调用成功

- **代码证据**：GET health 不发模型请求；HealthBadge 用 serverKey 或 byok 存在判断 ready。设置允许未测试直接保存；POST 测试仅调用 fast 档。
- **方向**：区分未配置、已配置未验证、快速模型可用、完整配置验证失败等状态；上次测试对应具体配置，修改后失效。
- **验收**：假密钥不能仅因保存成功就显示“模型就绪”；fast 成功、smart 失败不能宣称学习路径生成可用。
- **位置**：[health-badge.tsx](../../app/src/features/system/health-badge.tsx)、[health/route.ts](../../app/src/app/api/health/route.ts)。

### F17 · P2 · 标记学完必须等待模型画像更新成功

- **代码证据**：`complete()` 先 await profile，再保存 if_learned 和 completed_at；失败只有 toast。学习完成事实与模型判断绑在一起。
- **方向**：先在本地记录真实完成事件，再独立更新评估；区分“课程已完成”和“评估待更新”，失败可以重试。
- **验收**：断网或模型失败不丢失完成事实；重复重试不重复记时、不重复增加完成数。
- **位置**：[use-complete-session.ts](../../app/src/features/session/use-complete-session.ts)。

### F18 · P2 · 阅读区的 JS 位移动画未遵守减少动态效果偏好

- **代码证据**：SessionView 写死 `y:6` 与 0.24 秒 Motion 动画，没有 useReducedMotion 或全局 MotionConfig；CSS 的 animation-duration 无法覆盖 JS 驱动的 style 更新。StageList 已单独处理该偏好。
- **方向**：统一 Motion 层的 reduced-motion 策略，保留状态理解所需的静态反馈，取消不必要位移。
- **验收**：减少动态效果模式下阅读区不发生位移；正常模式仍保持连续性。动画执行时序需补充浏览器专项断言。
- **位置**：[session-view.tsx](../../app/src/features/session/session-view.tsx)、[layout.tsx](../../app/src/app/layout.tsx)。

## 从“功能齐全”到优秀体验的设计方向

以下不是全部必须立即新增的功能。每项都有明确的用户任务，应按核心旅程依次验证，避免堆功能。

| ID / 优先级 | 当前观察 | 建议方向 | 判断是否改好的方式 |
|---|---|---|---|
| D01 / P2 | 回访首页仍由口号和三段产品介绍主导；当前目标与下一课是较小的次级文案，“继续学习”先去路径页 | 回访首页优先显示当前课、上次读到的位置、待完成测验与一个继续按钮；直接恢复学习位置 | 回访者一次点击回到学习现场，能直接说出今天的下一步 |
| D02 / P2 | 五个主导航都是模块名；“画像”混合个人背景、模型推断、习惯和全局数据管理；移动端看不到明确的当前目标名称 | 以“学习、资料、进展、设置”等用户任务组织；当前目标做可识别的切换器；全局备份不依附某个目标画像 | 多目标用户始终知道自己在哪个目标下，能找到资料和数据恢复入口 |
| D03 / P2 | 首次创建要求用户先决定 3–10 门课程，却没有时长、难度或学习成果的对应关系 | 先问可投入时间、预期成果与自评基础；推荐课程数并解释，数量作为可调整结果；简历可选 | 用户无需理解内部课程粒度就能创建可执行路径 |
| D04 / P2 | 精炼目标和技能差距生成后直接进入后续步骤，用户无法确认“模型理解得对不对” | 在关键理解节点提供简短确认与就地修正；明确哪些是用户陈述、哪些是模型初步判断 | 发现错判已有技能时可以修正，无需新建整个目标 |

## 推荐的下一版核心体验

### 回到学习现场

回访首页顶部直接展示“继续：SQL 聚合与分组”，其下是“上次读到 GROUP BY · 测验尚未完成”。
一个主动作恢复现场，次级动作查看路径。目标、资料和进展服务于这次学习；品牌介绍保留在首次访问页面。
这些示例是建议文案，数据应从真实记录派生，不能以装饰性数据填充。

### 学习内容分阶段可用

创建目标时先建立可修正的理解，再规划路径。进入课程后，章节与教材逐步出现。
教材已经可读时，测验仍可在后台准备。页面允许暂停与离开，清楚说明哪些内容已经保存。
重试只恢复失败部分；重新生成先保留旧版本，再在成功后切换，避免先删除可用内容。

### 练习形成可解释的证据

每题有编辑、确认和反馈状态。错题反馈提供“回看对应章节”与“让导师换个例子”，下一步与错误内容对应。
交卷显示覆盖率、已评分结果和待评价题；完成课程先记录事实，再更新技能评估。
技能卡片能展开“依据哪次练习、哪一题、什么时候更新”，并允许用户指出误判。

### 保持克制，但让视觉重点跟随任务

沿用现有灰阶、青绿强调色、六级字号与三种字重。重点调整信息排序、阅读宽度、操作密度和状态连续性。
路径页面的视觉中心是当前课；阅读页面的中心是正文；进度页面的中心是证据与下一次练习。
技能关系图保留为有用的导航与解释工具；手机可以使用更合适的列表形态。

## 修改顺序与验收

1. **先保证结果可信与数据可恢复**：F01–F08、F10、F15；处理课程稳定身份、档案校验和评分口径，再调整相应组件。
2. **再让学习流程可以中断和继续**：F09、F11、F17，以及 D01、D04、D06、D09。不要先用动效掩盖状态丢失。
3. **完善移动端与共享组件**：F12–F14、F18，以及 D08、D11、D12。先修共享 Dialog、按钮长文本和输入行为，再逐页打磨。
4. **最后优化信息架构与长期使用**：D02、D03、D05、D07、D10。D07 的评分可信度应在第一批同步厘清，再做可视化呈现。

下一次实现建议一次选择一个有独立退出条件的改动范围；当前 M0–M7 已完成，不应把这份评审擅自记作旧里程碑继续迁移。
修改 API、存储关系、设计 token 时分别同步对应 wiki。涉及 LLM 参数、prompt 或图表时按 AGENTS 加载所需专项技能。

建议新增的回归场景：多选确认、简答待评分、漏答交卷、测验草稿恢复、重排后资料绑定、无损导入、坏档案拒绝、中文组合输入、教材就绪但出题失败、长标题、短视口弹窗、Markdown 目录、减少动态效果。
这些新增测试应在独立 spec 中正常加入，不能通过放宽或删除现有检查换取通过；本轮没有修改任何 gate / verify-ui 检查项。

测试数据也需要改进：现有 seed 将 Python 基础课与 Pandas 教材拼在一起，学习进度历史和当前画像也不是完全一致的状态。
应建立身份、内容和学习证据一致的档案，并补充中文长内容、多目标、未完成测验及错误状态。当前截图测试检查响应成功和 PNG 存在，未断言学习语义与跨步骤状态，因此 109 项通过并不意味着这些缺陷不存在。
