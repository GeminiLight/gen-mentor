# 操作型测验（issue #31）

## 目标与边界

在现有测验中支持步骤排序与 JSON 配置任务。排序使用拖拽及键盘/触控可用的上移下移按钮；配置题编辑真实 JSON 对象。两者在学习者主动检查后本地评分，无执行代码、终端、文件访问或额外网络请求。不把 JSON 配置题宣传为通用编程运行环境。

## 数据与反馈

`DocumentQuiz` 增加可选 `ordering_questions` 与 `configuration_questions`，保留 v1 档案兼容性。排序题包含唯一的 3–8 个步骤与完整零基索引排列，初始排列不能已是答案。配置题包含有效 JSON 对象的起始文本及 1–4 个可接受完整配置；起始配置必须需要修改。

编辑与确认分离；未检查的操作不计入回答数和正确率，交卷时沿用已有缺答确认流程。配置比较忽略对象键顺序、空白，保留值类型、数组顺序与额外字段的差异。题面须明确所有必需字段和值，避免把开放式任务当作唯一答案题。语法错误只做就地提示，输入仍保存在设备上。

检查后锁定答案，提供判定、解释及折叠参考答案。错误和跳过进入原有复习队列，练习不覆盖首次成绩。编辑草稿、确认状态、结果、复练全部支持刷新恢复及导出导入。

## 验收

- 单元验证契约、无效答案、对象比较、评分与复练映射、v1 档案往返。
- 浏览器验证键盘连续排序、拖拽、无效 JSON 修复、刷新、检查锁定、复练保留首次成绩。
- 手机和桌面、明暗主题截图，无水平溢出，axe 无 serious/critical。
- 生成端须验证新增题型能由文档产出，数量与题面可执行；不得伪造 LLM 录制回放。
- `make gate` 与 `GENMENTOR_LLM_MODE=replay make verify-ui` 全绿。

生成端扩展待仓库要求的 `claude-api` skill 缺失处理确认；交互、契约与评分可独立实现和验证。
